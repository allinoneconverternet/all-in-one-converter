{{BRAND}} 的安全

最近更新：2025年10月19日

{{BRAND}} 在你的浏览器内完成文件转换。你的文件从不上传到我们的服务器。以下是我们如何保护用户与应用本身。

威胁模型与理念

  • 数据最小化：文件与敏感内容保留在你的设备上。
  • 传输安全：所有页面均通过 HTTPS 提供，并启用 HSTS。
  • 隔离：在可用的情况下，繁重处理使用 WebAssembly/Web Workers，使任务在浏览器中沙箱化。

应用安全实践

  • 内容安全策略（CSP）：采用严格的默认策略，限制脚本来源与内联代码。
  • 子资源完整性（SRI）：在适用时，为第三方脚本/样式添加 integrity 属性进行防护。
  • 响应头：使用 COOP/COEP/CORP 与 Permissions-Policy，降低跨源风险并收紧高权限 API 的使用。
  • 供应链：持续跟踪依赖更新并及时应用安全补丁。
  • 广告沙箱化：广告位采用固定尺寸与沙箱 iframe，尽量减少版面位移并降低风险。

说明：具体策略可能因部署而异；如你是研究人员，欢迎与我们联系以获取详情。

你的文件与数据

  • 不上传：转换在你的浏览器内本地完成。
  • 不保留：我们不会在服务器上存储你的文件。
  • 仅限广告与同意：我们可能在你的同意偏好约束下处理少量标识符，以投放与衡量广告。详见我们的 隐私政策。

漏洞披露

如果你认为发现了安全问题，请发送邮件至 {{SECURITY_EMAIL}} 并附上细节。我们会在负责任披露框架下确认收到并尽快修复。

可选项：我们还提供 /.well-known/security.txt，其中包含最新的联系信息。

服务可用性

作为一款浏览器内工具，{{BRAND}} 依赖于你的设备性能与浏览器能力。我们致力于支持桌面与移动端主流浏览器的当前版本。
